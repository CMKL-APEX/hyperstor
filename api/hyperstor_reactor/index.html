Crate hyperstor_reactor

The per-core reactor (spec/08-engine.md §6.1, D3).

One thread, one io_uring, one executor. block_on runs a future and everything it spawns on the current thread until it completes. Futures are not Send: a task stays on the core that created it, as a PG stays on its reactor.

Ownership of buffers. An I/O operation takes ownership of its buffer and gives it back with the result (as in tokio-uring). If the future is dropped before the kernel completes the operation, the reactor keeps the buffer until the completion arrives, so the kernel never writes into freed memory.

Waking from other threads (chan, or any Waker cloned to another thread) pushes the task on a shared queue and writes an eventfd the ring always has a read armed on, so a reactor sleeping in io_uring_enter wakes up.

Modules§

chan
An unbounded multi-producer, single-consumer channel that works across threads and reactors: senders may run anywhere, the receiver awaits on its reactor.
fd
Waiting on and reading descriptors the reactor doesn’t wrap: eventfds (vhost-user’s kick and call, 11-frontends.md §11.1) and Unix sockets whose messages another library reads once they are ready.
file
Writes to a file or block device at offsets, on the reactor’s ring: the engine’s commits (I199), which used to wait in the device’s own calls and so held the reactor, pings included, for as long as the device took.
net
TCP on the reactor.
passthrough
io_uring passthrough commands (IORING_OP_URING_CMD): drivers that take their commands through io_uring, as ublk does (hyperstor-ublk, D94) and NVMe passthrough will (D3). Only the 16-byte command of a standard entry; a driver that needs 80 bytes keeps a ring of its own.
time
Timers on the reactor.

Functions§

block_on
Runs fut on a new reactor on this thread, with everything it spawns, until fut completes. Tasks still running then are dropped.
pin_to_cpu
Pins the calling thread to one CPU.
set_spin
Adaptive polling (04-decisions.md D41): after any activity, the reactor on this thread keeps polling for completions for spin before it sleeps in the kernel, so a request arriving soon after the last one doesn’t pay a thread wake-up. Polling still enters the kernel (without waiting) so network completions are delivered. Zero, the default, turns it off; storage reactors that own their cores turn it on.
spawn
Spawns a task on the current reactor.
