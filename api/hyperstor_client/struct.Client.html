pub async fn copy_volume( self: &Rc<Self>, id: u128, epoch: Option<u64>, pool: u32, new_id: u128, name: &str, p: &Progress, ) -> Result<Volume, ClientError>

Copies volume id into a new volume new_id named name in pool pool: its snapshot at epoch, or its head, which needs it detached (it is held meanwhile). The new volume is held while it fills, and deleted if the copy fails. Running it again after it stopped starts over, into the same new volume.

Source

pub async fn move_volume( self: &Rc<Self>, id: u128, pool: u32, p: &Progress, ) -> Result<Volume, ClientError>

Moves volume id to pool pool, keeping its id. Refused while it is attached, has snapshots (in the trash too), or another volume reads through it; a clone is flattened by the move. Running it again after it stopped finishes it, or starts over if the switch wasn’t made.

pub async fn snapshot( self: &Rc<Self>, id: u128, name: &str, ) -> Result<Snapshot, ClientError>

Takes a snapshot of volume id (10-volumes.md §10.3): its head epoch is recorded and moves on. If the volume is attached, its holder is quiesced first by the header’s primary (D103); if it doesn’t within 2 s the snapshot is abandoned (Busy).

Source

pub async fn snapshot_group( self: &Rc<Self>, ids: &[u128], name: &str, ) -> Result<(u128, Vec<(u128, Snapshot)>), ClientError>

Takes a snapshot of every volume in ids at one moment (a consistency group, 10-volumes.md §10.3): the group is recorded as preparing; every member’s holder is quiesced and held, so no member writes after any is cut; each member’s snapshot is taken, tagged with the group; the group is marked complete. If any step fails, the snapshots taken are deleted, the holds released and the group removed. Returns the group’s id and the snapshots.

Source

pub async fn group_complete( &self, gid: u128, ) -> Result<Option<bool>, ClientError>

Whether group gid is complete; None if there is no such group. A snapshot tagged with a group that isn’t complete is not one to use: its group failed, or is still being taken.

Source

pub async fn delete_group(self: &Rc<Self>, gid: u128) -> Result<(), ClientError>

Deletes group gid: every member’s snapshot tagged with it, then the group. Also how a group that stopped half-way is cleaned up.

Source

pub async fn delete_snapshot( self: &Rc<Self>, id: u128, epoch: u64, ) -> Result<(), ClientError>

Deletes the snapshot at epoch (10-volumes.md §10.3). Refused while a clone or rollback depends on it. Its versions are merged into the next newer version of each chunk without copying (D104), unless a later cut point (a snapshot, a clone’s or rollback’s parent, the head) still reads them through; versions nothing reads are deleted. A delete that stops half-way is resumed by deleting it again.

Source

pub async fn clone_snapshot( &self, id: u128, epoch: u64, name: &str, new_id: Option<u128>, ) -> Result<Volume, ClientError>

Creates volume new_id (or a random id) as a clone of the snapshot at epoch of volume id (10-volumes.md §10.4): a new branch of the same lineage (D21), allocating nothing.

Source

pub async fn rollback( self: &Rc<Self>, id: u128, epoch: u64, ) -> Result<Volume, ClientError>

Rolls volume id back to its snapshot at epoch (10-volumes.md §10.3): its head becomes a new branch cut from the snapshot, at once; then the old head’s versions newer than anything still reading them are deleted. The volume must be detached.

Source

pub async fn flatten(self: &Rc<Self>, id: u128) -> Result<Volume, ClientError>

Copies into clone id‘s own branch every block it still reads from its parents, then clears its chain (10-volumes.md §10.4): it then depends on nothing, and its parents’ snapshots can be deleted. Refused while it has snapshots taken before a rollback, which read through the chain.

pub async fn delete_volume(self: &Rc<Self>, id: u128) -> Result<(), ClientError>

Deletes a volume: marks it deleting, deletes its data, then its directory entry and header. A delete that stops half-way is resumed by deleting it again. An attached volume is refused: detach it, or take it over, first.

pub async fn attach_as( self: &Rc<Self>, id: u128, how: Take, label: &str, ) -> Result<Rc<Attached>, ClientError>

Self::attach, Self::take_over or Self::preempt, with label recorded with the lease instead of this client’s (D153).

Source

pub async fn take_over( self: &Rc<Self>, id: u128, ) -> Result<Rc<Attached>, ClientError>

Attaches volume id whose holder has died or is cut off (06-metadata.md §9, a forced takeover): waits until the holder’s lease has expired (up to 4 s after its last renewal, D75), blocklists it, then takes the lease. The old holder’s requests are refused from then on. A holder that keeps renewing is left alone: ClientError::LeaseHeld.

Source

pub async fn preempt( self: &Rc<Self>, id: u128, ) -> Result<Rc<Attached>, ClientError>

Attaches volume id from a live holder (an operator’s preemption): blocklists the holder first, so its renewals and I/O are refused, then waits for its lease to expire and takes it.

Source

pub async fn delegate( self: &Rc<Self>, id: u128, lease: u64, ) -> Result<Rc<Attached>, ClientError>

Opens volume id as delegate lease of its holder (D33, D151): I/O under the holder’s lease, which this client doesn’t renew. The holder gave lease out (Attached::add_delegate); refused unless the header lists it. Lost once it is fenced or no longer listed.

Source

pub async fn blocklist(&self, ids: &[u64]) -> Result<(), ClientError>

Blocklists client instances or lease identities (06-metadata.md §9, D150): returns once every storage node refuses them, and this client’s map has the entries.

pub async fn exec( &self, pool: u32, ns: u8, name: &[u8], ops: &[WireOp], ) -> Result<(), ClientError>

Applies ops to the object name of namespace ns in pool, atomically, if its assertions hold (06-metadata.md §4.2): an assertion that fails is ClientError::Server { code: Conflict, .. }, and nothing is changed.
