Snapshots, clones, rollback and flatten (10-volumes.md §10.3, §10.4; 04-decisions.md D10, D21, D101, D103, D104).

A chunk’s data in a branch is a set of versions, one per head epoch it was written in (08-engine.md §7.2). A snapshot is a compare-and-set on the header: it records the head epoch, and the head moves on; nothing is copied. A clone or a rollback is a new branch of the lineage, cut from a snapshot; its reads go through its chain of parents.

The lineage object l/{lineage} gives out branch numbers and records each branch (as key–value entries): its volume, the chain it was cut with, and the epoch it was flattened at, if it was. A snapshot is in use while a branch that still reads its chain has it in its chain; a flattened branch still does while its volume has snapshots from before the flatten (01-implementation-notes.md I115). Clone and delete race safely: a delete marks the snapshot deleting before it looks for dependents, and a clone records itself before it checks the snapshot is still live.
